\section{Higher-order Goal \BvrHint{Real-world impact}}
The Smart Library Seat Management System aims to transform the chaotic process of finding and retaining study spaces in college libraries into an organized, transparent, and fair digital experience. The system addresses the common issue of students blocking seats for extended periods while away, leading to wasted capacity and frustration for others. 

The engineering objective is to build a robust software system that coordinates students, seating inventory, time-based policies, and real-time mapping through a unified workflow. This project offers a direct real-world use case while providing substantial software complexity to fulfill the learning outcomes of UCS503.

\section{Problem Statement}
In peak academic periods, library seating becomes a scarce resource. Existing methods rely entirely on physical roaming, which is time-consuming and inefficient.

The major problems are:
\begin{itemize}[leftmargin=0.7cm]
    \item \textbf{Uncertain availability:} Students waste time navigating multiple floors to find an empty seat.
    \item \textbf{Unfair Resource Blocking:} Students leave their belongings to 'reserve' a seat for hours while they are out for lunch or classes.
    \item \textbf{Poor Workflow Visibility:} Librarians cannot track which seats are genuinely occupied versus merely blocked.
    \item \textbf{No Data-Driven Planning:} Lack of analytics regarding peak library hours, preferred zones, and overall seating utilization limits effective infrastructure planning.
\end{itemize}

\section{Proposed Solution \BvrHint{Software Proposition}}
The system will be developed as a responsive web-based platform connecting students and library administrators.

The proposed system will provide:
\begin{itemize}[leftmargin=0.7cm]
    \item \textbf{Real-Time Floor Map:} A visual representation of seat statuses (Available, Occupied, Temporarily Away) across different floors.
    \item \textbf{Smart Seat Finder:} Recommendations based on user preferences (e.g., quiet zone, charging port).
    \item \textbf{Temporary Away Permits:} An enforced countdown timer (e.g., 30 minutes) allowing students to take breaks. If they overstay, the seat is automatically marked as available.
    \item \textbf{Fair-Use Algorithms:} Limits on the number of breaks a student can take per day to prevent abuse.
    \item \textbf{Operations Dashboard:} Administrators can monitor live occupancy, override seat statuses, and view utilization metrics.
\end{itemize}

\section{Core Workflow}
The principal workflow is:
\begin{enumerate}[leftmargin=0.7cm]
    \item Student authenticates via their college ID/SSO.
    \item Student checks the interactive floor map or uses the Smart Finder for recommendations.
    \item Student selects an available seat and digitally checks in.
    \item If a break is needed, the student activates a ``Temporary Away'' permit.
    \item A countdown timer begins. The student must check back in before the timer expires.
    \item If the timer expires, the seat is automatically released.
    \item Upon leaving the library, the student checks out, permanently freeing the seat.
\end{enumerate}

\section{Why This is Suitable for UCS503}
This project goes beyond a standard CRUD application. The core challenge involves coordinating real-time state management, time-based automated triggers, concurrent user access, and dynamic visual layouts.

This creates a practical software engineering problem involving:
\begin{itemize}[leftmargin=0.7cm]
    \item UML and dynamic state workflow modelling;
    \item Concurrency control and database lock design;
    \item API design for real-time state propagation (e.g., WebSockets);
    \item Agile backlog and sprint management;
    \item Software testing and state verification.
\end{itemize}

\section{Requirements Engineering}
\subsection{Stakeholders}
\begin{itemize}[leftmargin=0.7cm]
    \item Students (End Users)
    \item Library Administrators (Operations)
    \item IT System Maintainers
\end{itemize}

\subsection{Representative Functional Requirements}
\begin{enumerate}[leftmargin=0.7cm]
    \item The system shall allow students to view real-time seat availability.
    \item The system shall enforce a maximum time limit for the 'Temporary Away' status.
    \item The system shall automatically transition a seat from 'Away' to 'Available' upon timer expiration.
    \item The system shall prevent a single user from occupying multiple seats concurrently.
    \item The system shall generate daily occupancy reports for administrators.
\end{enumerate}

\subsection{Representative Non-functional Requirements}
\begin{itemize}[leftmargin=0.7cm]
    \item \textbf{Performance:} Status updates should reflect on all connected clients within 2 seconds.
    \item \textbf{Reliability:} The system must handle high concurrent check-ins during exam periods.
    \item \textbf{Energy efficiency:} The UI will utilize efficient state polling or WebSockets to minimize client-side battery drain.
\end{itemize}

\section{UML and System Modelling}
The project will produce the following models:
\begin{itemize}[leftmargin=0.7cm]
    \item \textbf{Use-case diagram:} Student check-ins vs Admin overrides.
    \item \textbf{Activity diagram:} The Temporary Away workflow and timer expiration.
    \item \textbf{Sequence diagram:} Client-server interaction during a concurrent seat booking attempt.
    \item \textbf{State diagram:} Seat lifecycle (Available, Occupied, Away, Maintenance).
    \item \textbf{ER diagram:} Relational data model for Users, Seats, Zones, and Sessions.
\end{itemize}

\section{Software Architecture}
A three-tier architecture with MVC principles is proposed.
\begin{itemize}[leftmargin=0.7cm]
    \item \textbf{Presentation layer:} Responsive web interface.
    \item \textbf{Application layer:} REST/WebSocket APIs handling timers and concurrency logic.
    \item \textbf{Data layer:} Relational database containing layout metadata and historical sessions.
\end{itemize}

\section{Green Software Engineering}
The project will incorporate:
\begin{itemize}[leftmargin=0.7cm]
    \item Event-driven WebSocket updates instead of aggressive client-side HTTP polling.
    \item Dark-mode support for OLED power savings.
    \item Minimal payload sizes for API responses to reduce network overhead.
\end{itemize}
